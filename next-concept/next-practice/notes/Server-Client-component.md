# Server and Client Component

## By default, layout and pages are server Components, which lets you fetch data and render parts of your UI on the server.

## when you need interactivity or browser APIs, you can use client components.


# When to use Server and Client Components

# Use Client Components when you need:
- ```state``` and ```event handlers``` Eg: onClick and onChnage
- If you need ```Lifecycle logic``` Eg: useEffect
- Browser-only APIs. Eg: localStorage, window, Navigator.geolocation, etc
- Custom hooks.

# use Server Components when you need:
- ```Data Fetching```: Fetch data directly on the server for faster and efficient loading.

- ```Security```: Keep API keys and secrets safe by not exposing them to the client.

- ```Less JavaScript```: Reduce bundle size by not sending unnecessary JS to the browser.

- ```Better FCP```: Render content faster to improve initial page load experience.

- ```Streaming```: Load UI progressively in chunks for better perceived performance.


# How do Server and Client Components work in Next.js?

## On the Server

# React Server Components (RSC) & Rendering in Next.js

## 📌 Overview

In Next.js, rendering on the server is handled using React’s APIs. Instead of rendering everything at once, the work is **split into chunks** based on **route segments** like layouts and pages.

---

## ⚙️ How Rendering Works (Server Side)

When a request is made:

1. The route is split into segments:
   - Layouts
   - Pages

2. Rendering happens in parts (chunks), not all at once.

3. Server Components are processed first.

---

## 🧩 What is RSC Payload?

**RSC (React Server Component) Payload** is a special data format generated by the server.

> It is a **compact binary representation of the rendered Server Components tree**.

---

## 📦 What RSC Payload Contains

The RSC Payload includes:

- ✅ Rendered output of **Server Components**
- ✅ **Placeholders** for Client Components
- ✅ References to **Client Component JavaScript files**
- ✅ **Props/data** passed from Server → Client Components

---

## 🔄 Rendering Flow

1. Server Components render → converted into **RSC Payload**
2. RSC Payload + Client Components → used to generate **HTML**
3. HTML is sent to the browser
4. Browser uses RSC Payload to:
   - Update DOM
   - Hydrate Client Components

---

## 🧠 Key Concepts

- RSC Payload is **NOT HTML**
- It is an **intermediate format (blueprint of UI)**
- Client Components are **not fully rendered in RSC**
- They are referenced and hydrated later in the browser

---

## ⚡ Why This Approach?

- 🚀 Faster rendering (chunk-based)
- 📉 Less JavaScript sent to browser
- 🔐 Better security (server-side logic stays on server)
- ⚡ Supports streaming (progressive UI loading)

---

## 📝 One-Line Summary

> RSC Payload is a compact data format that represents the Server Component tree and helps React efficiently render and hydrate the UI on the client.

---


# What is Hydration?
Hydration is React's process for attaching event handlers to the DOM, to make the static HTML interactive.

# Client Component
- To make client component use ```use client``` directive on top of component.
- Once a file is marked with ```"use client"```, all its ````imports and child components```` are ```considered part of the client bundle```.
- This means you ```don't need``` to add the ```directive``` to ```every component``` that is intended for the client.
